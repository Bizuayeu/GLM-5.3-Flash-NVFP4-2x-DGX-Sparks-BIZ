# ZCode PreToolUse ガード

[English](README.md)

ZCodeを `yolo` で動かしたまま、既にあるものを変える前だけ確認を求めるhookです。
権限の連鎖、モデルの上限、裏付けの実測は
[ハーネス連携](../../docs/harnesses.ja.md#zcodeの権限モードモデル上限既存ファイルガード)にあります。
本書は導入手順だけを扱います。

## hookである理由

ZCodeは `yolo` をプロジェクトの権限規則より先に、`disallowedTools` より先に評価するので、
パスの規則では狭められません。方針の `allow` を確認に戻せる場所は `PreToolUse` hookだけです。
権限の記述子には「そのファイルは既にある」という概念がなく、`Write` と `Edit` は一つの権限を共有し、
削除は `Bash` を通ります。

## 導入

1. `exists-guard.cjs` をこのリポジトリの外、たとえばクライアントの設定の隣の `hooks` ディレクトリへ複写します。
2. `config.hooks.example.json` をクライアントの設定（`config.json`）へ併合し、`hooks.enabled` をtrueにします。
   項目のtimeoutは上位の `hooks.timeoutMs` に委ねます。先に動いている設定の控えを取ってください。スキーマに合わない項目は設定全体を無効にし、
   モデル設定が無いといった無関係な誤りとして表面化します。
3. `command` には絶対パスのインタプリタを書きます。ランチャーから起動したデスクトップ版は
   shellの `PATH` を継ぎません。runtimeは終了コード0を判定、2を拒否として読み、それ以外の終了、
   spawnの失敗、timeoutのいずれでも該当するtool呼び出しを失敗にします。

## 確認

クライアントに新しいファイルを作らせ（確認なしに通るはず）、次に既存のファイルを変えさせます（確認が出るはず）。
代わりに全部が拒否されるならhookが起動していません。設定の控えを戻し、インタプリタのパスを確かめてください。
`ZCODE_GUARD_LOG` に書き込めるパスを設定すると、hookの生のstdin（ファイル内容を含む）を追記します。
payloadの形を調べる間だけ使い、済んだら外してください。

## 限界

shellの関門はコマンド行の文字列ヒューリスティックで、見逃しがあります。保守的な代替は
`Bash` の呼び出しをすべて確認にすることです。hookはmatcherに名前のあるtool（`Write|Edit|Bash`）しか見ないので、
将来のファイル書き込みtoolはmatcherを広げない限り通ります。守るのは存在であって内容ではありません。
承認した上書きは、上書きそのものです。
